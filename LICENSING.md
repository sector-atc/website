# Licensing

We build SECTOR as an open project and want shared improvements to remain available to the community. We use different licenses for software and content, with explicit boundaries for third-party material and branding.

| Material we create for SECTOR | License |
|---|---|
| Application code, libraries, SDKs, tools, scripts, configuration, shaders, generators, and executable code examples | AGPL-3.0-only |
| Documentation, guides, website prose, community guidance, original diagrams and illustrations | CC-BY-SA-4.0 |
| Original synthetic datasets and fixtures | CC-BY-SA-4.0 |
| Logos and project branding | Separate branding policy; no general reuse grant |
| Third-party code, starter material, datasets, fonts, artwork, and other assets | Their existing licenses and notices |

We license our software under GNU AGPL version 3 **only**, not “version 3 or later”. The full text is in LICENSE and LICENSES/AGPL-3.0-only.txt. We license our original content and synthetic datasets under Creative Commons Attribution-ShareAlike 4.0 International; see LICENSES/CC-BY-SA-4.0.txt. These grants apply to existing and future SECTOR-authored material of the stated categories unless a specific notice identifies an exception. They do not replace third-party terms.

## What we expect from reuse

For covered software distributions, we require the corresponding source and notices under the AGPL. Modified versions that support remote user interaction must prominently offer corresponding source to those users under section 13. We will implement the required source offer with network and companion functionality; a public repository alone does not replace the license obligations.

For shared content adaptations, we require attribution, identification of changes, and the same or a compatible license as required by CC BY-SA 4.0. Commercial reuse is permitted. Content and database rights do not automatically impose a license on independent software that reads the data. We do not claim rights in unprotected facts.

We keep external navigation data separate: an importer license does not grant redistribution rights for the imported data. We record provenance, publication rights, attribution, and transformations for every external asset or dataset.

## Contributions and ownership

We accept original software contributions under AGPL-3.0-only and original content and synthetic-data contributions under CC-BY-SA-4.0. Contributors retain their copyright and must have authority to submit their work. We require third-party material to be identified with its actual terms. We do not require copyright assignment or establish a CLA through this policy. Ownership of a GitHub organization does not transfer contributors’ copyright.

## Notices and exceptions

We use short SPDX notices for new source files, naming the actual copyright holder:

```text
// SPDX-FileCopyrightText: YEAR Actual copyright holder
// SPDX-License-Identifier: AGPL-3.0-only
```

For prose Markdown we use `<!-- SPDX-License-Identifier: CC-BY-SA-4.0 -->`; executable examples remain AGPL-3.0-only as stated above. We preserve existing upstream notices rather than relabeling starter-template files. Generated files, binary assets, and datasets need an accompanying rights notice when inline comments are unsuitable. We review dependencies, starter assets, and integration terms before releases.

Our logo and branding policy is in BRANDING.md.
